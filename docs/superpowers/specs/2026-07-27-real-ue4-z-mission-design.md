# 真实 UE4 四旋翼 Z 字任务联调设计

## 目标

本轮联调以我方 HIL/Simulink 侧为协议 V2.0 中的 `Simulink` 角色，连接真实 UE4 侧的 Python Bridge：

- HIL 是 TCP 客户端，连接 `192.168.100.172:5000`。
- 不启动、不连接 WebSocket；保留现有 WebSocket 源代码。
- 不使用本地模拟 UE4；保留模拟 UE4 脚本，供以后独立测试。
- 使用新生成的四旋翼飞行动力学模型，执行“起飞至 20 m、Z 字航线、降落”任务。
- 在终端可视化并在线调整限定的模型参数。
- 发送给 UE4 的报文严格且仅限于通信协议 V2.0 定义的格式和字段。

## 范围和清理边界

在实施开始时，删除旧的运行/测试产物：

- `test_output/`
- `executables/`
- `runtime/`
- `logs/`（如存在）
- 以上目录中保存的旧生成模型、可执行程序、构建中间文件、运行日志和测试数据

保留以下内容：

- `c_core/`、`python_services/`、`matlab_scripts/`、`tests/` 等源代码
- `scripts/mini_ue4_sim.py`
- 现有 WebSocket 源代码，但本轮启动脚本不得启动或连接它
- 现有设计文档和协议文档

清理仅针对上述产物目录，不删除模型源码、模拟 UE4 脚本或版本控制内容。

## 架构

采用“SLX 动力学植物 + C 实时任务控制器”方案：任务规划不嵌入模型根输入，不因更换航点而重新生成模型。

```text
mission_z.json
      │
      ▼
C 实时任务控制器（航点状态机、位置/姿态控制、电机混控）
      │  电机控制、环境、故障输入
      ▼
四旋翼 SLX 生成的 C 模型（1 ms 动力学步进）
      │  内部飞行状态
      ├──────────────► 终端仪表盘（本地参数/状态显示）
      │
      ▼ 每 20 ms
Python TCP Bridge ──TCP V2.0──► 真实 UE4 Bridge（192.168.100.172:5000）
```

SLX 模型负责六自由度四旋翼动力学、执行机构响应、重力、阻力和风场作用；C 实时层负责读取任务 JSON、顺序跟踪航点、生成电机控制量、维护任务状态和处理在线参数命令。

## 模型接口与运行参数

模型根接口遵循既有 HIL 合同，供 C 运行层调用：

| 类别 | 内容 | 用途 |
| --- | --- | --- |
| 输入 | 四路归一化电机控制量、风场、故障/电机效率 | 实时动力学计算 |
| 内部输出 | 位置、姿态、线速度、角速度、模型时间和运行状态 | 控制器反馈、终端显示、协议映射 |
| 热调参数 | 质量、转动惯量、推力系数、力矩系数、线性阻力、角阻尼、风速、电机效率 | 终端命令在下一个模型周期生效 |
| 非热调参数 | 固定步长、状态维度、接口维度、数据类型、模型结构 | 禁止在线修改，需重新生成/编译 |

模型参数修改只影响 C 模型的可调参数存储；不修改 `.slx` 文件。终端显示当前参数值、参数范围、当前任务阶段、航点编号、模型时间、位置姿态、通信会话状态和最后错误。

## 任务 JSON

运行脚本接收任务 JSON 路径。默认任务描述以下五个阶段：

1. 地面原点 `(0, 0, 0)`；
2. 垂直起飞到 `(0, 0, 20)`；
3. 高度保持 20 m，依次通过 Z 字航点；
4. 到达末端航点后垂直下降；
5. 触地后结束任务。

默认 Z 字平面航线为：

```text
(0, 0, 20) → (40, 0, 20) → (0, 20, 20) → (40, 20, 20)
```

JSON 还包含任务 ID、每个航点的目标速度和到达容差。控制器使用位置误差、速度误差和航向目标生成姿态/推力命令，再通过电机混控形成四路模型输入。任务 JSON 同时映射为协议 V2.0 的 `mission_plan`，但协议消息只用于视景展示，不直接作为模型根输入。

## UE4 通信合同

我方是 TCP 客户端，严格遵循 `Simulink_三维视景通信协议草案_V2.0.md`：

- 每帧：`[4 字节大端无符号长度][UTF-8 JSON]`；JSON 正文最大 1 MB。
- 外层字段固定为 `protocol_version`、`type`、`seq`、`vehicle_id`、`data`。
- `protocol_version` 为 `"2.0"`，`vehicle_id` 为 `"Drone1"`；所有数值必须是有限实数。
- 坐标为 `x_forward_y_right_height_up`，单位 m；姿态为 roll/pitch/yaw，单位 rad。
- 同一连接内 `seq` 严格单调递增；重连后从 1 开始。

会话严格按如下状态机执行：

```text
CONNECT
  → hello
  → 等待并校验 ack(ref_type=hello, accepted=true)
  → mission_plan
  → 等待并校验 ack(ref_type=mission_plan, accepted=true)
  → 以 50 Hz（20 ms）发送 vehicle_state
  → simulation_event(mission_end)
  → 等待并校验 ack(ref_type=simulation_event, accepted=true)
  → END
```

收到 `error`、`accepted=false`、ACK 超时或 TCP 断连时，不进入下一状态；记录原因并停止任务。断连后的恢复方式为重新连接并从 `hello` 开始会话。`vehicle_state` 不等待逐帧 ACK，只在收到 `error` 时处理异常。

发送给 UE4 的消息**仅**为协议列出的 `hello`、`mission_plan`、`vehicle_state`、`simulation_event`。不会发送加速度、模型参数、执行时间、故障诊断或任何私有字段。

`vehicle_state.data` 仅包含协议 V2.0 定义的字段：`mission_id`、`sim_time`、`position`、`attitude`，以及需要时的 `velocity`、`angular_velocity` 和 `flight_state`。状态流固定为 50 Hz；`hello.data.state_rate_hz` 固定为 `50`。

## 终端仪表盘

启动脚本启动模型运行时和终端仪表盘，不启动 WebSocket 服务。仪表盘循环显示：

- 当前会话阶段、目标地址、最近 ACK/Error；
- 任务 ID、飞行阶段、当前/下一航点；
- 位置、姿态、速度、模型时间；
- 模型可调参数及其当前值和允许范围。

支持 `set <parameter> <value>`、`status`、`help`、`quit` 命令。参数写入采用校验后原子提交，在下一个 1 ms 模型周期前生效；非法名称、越界数值或非有限数值拒绝并显示错误。

## 验收标准

- 启动脚本以任务 JSON 为输入，且不启动或连接 WebSocket。
- 成功连接真实 UE4 地址，完成 `hello` 与 `mission_plan` 的 ACK 校验。
- UE4 先显示任务规划；随后在 50 Hz 下仅接收合规的 V2.0 `vehicle_state`。
- 无人机先达到 20 m，再完成指定 Z 字航线，最后降落并收到 `mission_end` ACK。
- 终端可显示状态并成功调整至少质量、阻力系数、风速和电机效率；非法修改被拒绝。
- 任意 ACK 异常、协议错误或断连均停止向后推进任务，并保留可诊断日志。
- 不向 UE4 发送协议外字段或消息类型。

## 风险与边界

- 真实 UE4 服务器地址已确认为 `192.168.100.172:5000`；若 DHCP 导致地址变化，需要更新运行配置。
- 本轮为四旋翼动力学联调，不接 PX4、CAN、UART 或 WebSocket。
- 50 Hz 是 UE4 状态发布频率；模型积分仍保持 1 ms。
- 实际轨迹受在线物理参数调整影响，控制器以航点容差判定到达，不能承诺参数被极端修改后仍保持理想轨迹。
