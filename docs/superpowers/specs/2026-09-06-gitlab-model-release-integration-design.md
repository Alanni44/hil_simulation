# GitLab 模型 Release 集成设计

## 目标

让 3.6 HIL 系统从 GitLab 的受控 Release 中选择和暂存模型包，并将已核验的包交给现有构建与部署链路。该功能只读访问 GitLab，不管理分支、合并请求、提交或 GitLab 用户。

## 范围

- 在 HIL 服务中增加可禁用的 GitLab REST API 适配器。
- 支持列出项目白名单中的 Release，并展示标签、提交、发布时间和模型包资产。
- 支持暂存指定 Release 的模型包，校验并原子导入既有受控模型包目录。
- 复用已有 `build_package` 和 `deploy_package`，不修改 C 实时核和模型包合同。
- 将现有单文件 HTML 原型纳入版本控制，并把模型工程、构建和部署界面接入现有 WebSocket 协议。
- 为每一次模型选择、暂存、构建和部署保存可审计的 JSON 记录。

## 非目标

- 不创建、更新或删除 GitLab 项目、分支、标签、Release、文件或合并请求。
- 不实现 GitLab 用户、角色和审批管理；GitLab 仍是 3.2 的版本管理权威。
- 不实现远程模型运算设备文件传输。服务运行于目标机时，导入受控本地目录即为部署前置条件。
- 本轮不启动伪 GitLab HTTP 服务，也不连接真实 GitLab 实例。

## 配置与安全边界

`config.yaml` 仅保存非敏感配置：启用状态、GitLab 基础地址、项目白名单、超时和允许的 Release 资产文件名。访问令牌只从 `HIL_GITLAB_TOKEN` 环境变量读取，绝不写入页面、配置、日志、审计记录或 Git。

未启用、基础地址为空、白名单为空或令牌缺失时，适配器返回明确的 `NOT_CONFIGURED` 状态，不发起网络请求。所有 GitLab 请求使用只读令牌权限，并限制 HTTPS 方案；运行时对响应大小、重定向、超时和 JSON 结构设上限。

## 架构与数据流

```text
HTML 模型工程页面
  -> HIL WebSocket 命令
  -> GitLab adapter (只读 Release 和资产请求)
  -> 隔离暂存文件
  -> 解包和现有 validate_package
  -> 原子导入 CONTROLLED_PACKAGE_ROOT
  -> build_package / deploy_package
```

浏览器只接收经过 HIL 服务筛选的项目、Release 和暂存状态。它不接触 GitLab URL 中的认证信息、访问令牌或原始响应中无关的用户资料。

## 服务接口

- `gitlab_status`：返回集成是否配置、允许项目数量和不含敏感信息的状态。
- `gitlab_list_releases`：按白名单项目返回可选 Release；返回项目路径、标签、提交 SHA、发布时间和可识别资产。
- `gitlab_stage_release`：请求指定项目和标签，下载指定模型包资产，校验哈希/包清单/合同，并导入受控目录；返回 `model_ref`、`model_revision_ref`、包路径和所有适合后续构建的哈希。
- `gitlab_history`：返回 HIL 本地审计记录，不向 GitLab 写入状态。

所有成功与失败操作都写入独立 JSON 审计记录。记录包含请求 ID、项目、标签、提交、模型哈希、合同哈希、结果、操作者标识（若客户端提供）和 UTC 时间；不得记录令牌。

## 前端

将原型保存为版本控制下的静态页面。模型工程页会调用 `gitlab_status` 和 `gitlab_list_releases`，由用户选择 Release 后调用 `gitlab_stage_release`。构建页使用暂存结果调用现有 `build_package` 或 `deploy_package`，并显示服务返回的真实阶段、日志路径和错误原因。

在未配置状态，页面保留预览布局，但禁用受控 Release 选择、暂存、构建和部署按钮，并显示配置所需项。原型中的示例工程、虚假构建成功日志和仅修改 DOM 的部署状态将被替换为真实服务回执。

## 错误处理

- 认证失败、权限不足、项目不在白名单、Release/资产不存在、下载超时、资产超限、包校验失败和目标目录冲突均返回结构化拒绝原因。
- 暂存失败不会改变受控模型目录；只有完整下载、校验和目录同步全部成功后才原子发布。
- 适配器只接受白名单项目与配置的资产名，拒绝用户提交任意 URL、文件路径或 Git 引用。
- 构建和部署继续使用既有单实例、验证和健康检查规则。

## 验证

本轮不启动伪 GitLab 服务，也不连接真实 GitLab。测试覆盖配置禁用、令牌缺失、请求构造、白名单限制、响应解析、审计记录脱敏、下载流大小限制、临时目录清理和将已验证包导入受控目录的行为。真实 GitLab 端到端验证待基础地址、项目路径和只读令牌由部署人员提供后执行。

## 完成标准

- GitLab 未配置时系统安全失败且页面不误报可用。
- 已配置时系统只能读取白名单项目的 Release，并且不会写入 GitLab。
- 只有通过现有模型包验证的 Release 资产能够进入受控模型目录。
- 暂存结果可直接作为已有构建/部署命令的输入。
- 页面不包含静态成功状态，也不暴露令牌。
- 新增单元测试和既有回归测试通过；真实 GitLab 联调明确标注为待执行。
